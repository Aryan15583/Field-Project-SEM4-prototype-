# Put Codeingo online: Vercel + Render + Neon (all free tiers)

| Part | Where | Why |
|---|---|---|
| Website (Next.js) | **Vercel** | made for Next.js |
| API (FastAPI) | **Render** web service | needs an always-running Python server |
| Database (PostgreSQL) | **Neon** | free hosted Postgres |
| Redis (rate limiting) | **Render Key Value** | created by `render.yaml` |

The website forwards every `/api/...` request to the API (`API_ORIGIN`), so the browser only ever sees one site -
cookies, CSRF protection and the security headers work exactly as on your PC.

> Pick your Vercel project name now (e.g. `codeingo`). Your site will be `https://codeingo.vercel.app` -
> below that's called **SITE**. If the name is taken, choose another and use it everywhere.

---

## 1. Database - Neon (5 min)

1. Sign up at <https://neon.tech> (log in with GitHub) -> **Create project** (any region close to you).
2. On the dashboard click **Connect**, switch **Connection pooling OFF**, and copy the connection string
   (`postgresql://...neon.tech/neondb?sslmode=require`). That's your **DATABASE_URL**.

## 2. Two secret keys (1 min)

In `backend` on your PC (with the venv active):

```powershell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

That prints your **ENCRYPTION_KEY** (it encrypts authenticator secrets - keep it safe and never change it).
`SECRET_KEY` is generated by Render for you.

## 3. Google sign-in & email (10 min)

* **Google**: in Google Cloud Console -> Credentials -> your OAuth client, add the redirect URI
  `SITE/api/auth/google/callback` and the JavaScript origin `SITE`. Click **Publish app** on the consent screen so
  anyone can sign in.
* **Email codes** (required in production): Gmail works. Google Account -> Security -> 2-Step Verification ->
  **App passwords** -> create one -> copy the 16 letters (no spaces). That's your **SMTP_PASSWORD**.

## 4. API - Render (10 min)

1. Sign up at <https://render.com> with GitHub and allow access to this repository.
2. **New -> Blueprint** -> pick the repo and the branch with this code. Render reads `render.yaml` and asks for:

   | Key | Value |
   |---|---|
   | DATABASE_URL | the Neon string from step 1 |
   | ENCRYPTION_KEY | from step 2 |
   | PUBLIC_URL | `SITE` (e.g. `https://codeingo.vercel.app`) |
   | ALLOWED_HOSTS | `["codeingo-api.onrender.com"]` (your Render service's host) |
   | ADMIN_EMAILS | `["your.gmail@gmail.com"]` |
   | GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET | from Google Cloud |
   | GOOGLE_REDIRECT_URI | `SITE/api/auth/google/callback` |
   | SMTP_HOST | `smtp.gmail.com` |
   | SMTP_USERNAME | your Gmail address |
   | SMTP_PASSWORD | the App Password |
   | SMTP_FROM | `Codeingo <your.gmail@gmail.com>` |

3. **Apply**. The first build takes ~5 minutes. When it's live, open
   `https://codeingo-api.onrender.com/api/health` - you should see `{"status":"ok"}`.
   (If the service got a different name, use its URL and fix ALLOWED_HOSTS to match.)

The API refuses to start with an unsafe production setting and says exactly which one in the Render **Logs** tab.

## 5. Website - Vercel (5 min)

1. Sign up at <https://vercel.com> with GitHub -> **Add New -> Project** -> import the repo.
2. **Project name**: the one you picked (so the URL is `SITE`).
3. **Root Directory**: `frontend` (framework is detected as Next.js).
4. **Environment Variables**: `API_ORIGIN` = `https://codeingo-api.onrender.com`
5. Under **Settings -> Git**, set the production branch to the branch with this code (or merge it into `main`).
6. **Deploy**. Open `SITE` - sign in with Google, enter the emailed code, and you're in.

Every push to that branch redeploys both the website (Vercel) and the API (Render) automatically.

---

## Good to know

* **Free Render services sleep** after 15 minutes without visitors; the first request after that takes ~50 s.
  The paid Starter plan (about $7/month) keeps it awake - and lets the streak-reminder timer run all day.
* **Neon free** auto-pauses too, and wakes in about a second.
* **Java / C / C++ run buttons**: without a code-runner sandbox those exercises are checked with patterns
  (everything else runs in the learner's browser). See the README for the optional runner.
* **Passkeys** work automatically - they need HTTPS, which Vercel provides.
* Changing the site address later? Update PUBLIC_URL, GOOGLE_REDIRECT_URI and the Google Cloud redirect URI.
